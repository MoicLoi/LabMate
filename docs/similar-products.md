# 同类产品调研与定位

> 调研时间：2026-11 ｜ 方法：公开应用商店页、产品介绍页、厂商文档的桌面检索（未逐个安装试用）。
> 结论用于判断"值不值得自己做"，不构成竞品评测。

## 一、先把需求拆开

你说的这套东西，其实是 5 个能力叠在一起：

1. **把预设表格的照片转成结构化 JSON**（不是"识别成文字"，而是"识别成有 schema 的数据"）
2. **按固定模板入库**（同一张表每次识别，列名/类型/单位一致，可比较、可统计）
3. **LaTeX 公式**（输入/生成/渲染，进得了报告）
4. **三分支处理实验问题**（答疑 / 可能性 / 优先级，可复用的决策树）
5. **实验流程录入 + 报告产出**

市面上的产品通常只覆盖其中 1~2 个。

## 二、四类相邻产品

### 1) 表格 OCR / 扫描类
**代表**：金鸣表格文字识别、夸克扫描王、白描、各类"图片转 Excel"工具。

- 有：[金鸣表格文字识别](http://m.appchina.com/app/io.dcloud.H5F5CBC50) 这类工具主打"拍照识别表格 → 导出 Excel"，识别能力成熟。
- 没有：不认识"这是滴定数据表"，不会按你的列定义校验，不会把结果挂到某个实验下，也不会生成结论与报告。
- 差异：LabMate 的模板是**语义模板**（列 key、类型、小数位、单位），输出直接是入库 JSON，而不是一张 Excel。

### 2) 电子实验记录本（ELN）
**代表**：[鹰谷电子实验记录本 InELN](https://baike.baidu.com/item/%E9%B9%B0%E8%B0%B7%E7%94%B5%E5%AD%90%E5%AE%9E%E9%AA%8C%E8%AE%B0%E5%BD%95%E6%9C%AC/23638036)、App Store 上的[电子实验记录本](https://apps.apple.com/cn/app/%E7%94%B5%E5%AD%90%E5%AE%9E%E9%AA%8C%E8%AE%B0%E5%BD%95%E6%9C%AC/id1336794795)。

- 有：实验记录、版本留痕、合规审计、团队协作，面向科研机构/药企。
- 没有：轻量、面向学生、拍照转预设 JSON、分支答疑、LaTeX 即时渲染。
- 差异：ELN 是"把纸换电子"，LabMate 是"把纸上的数据变成能算、能比、能写进报告的结构"。

### 3) 虚拟实验 / 仿真
**代表**：[NB 实验室（NOBOOK）](https://apps.apple.com/hk/app/nb%E5%AE%9E%E9%AA%8C%E5%AE%A4/id1265400377)（[小米应用商店页](https://app.xiaomi.com/details?id=com.nobook.experimentalStu)）。

- 有：器材拖拽、现象仿真、探究式学习，很适合预习和演示。
- 没有：不处理你在真实实验室里拍的那张手写表，不做数据入库、不做报告。
- 差异：一个是"做实验"，一个是"记录并处理做完的实验"。

### 4) AI 笔记 / AI 扫描笔记
**代表**：[Notewise](https://apps.appfollow.io/android/notewise-notes-pdf/com.yygg.note.app)、[Jnotes](https://play.google.com/store/apps/details?id=com.jideos.jnotes.overseas.google)。

- 有：手写、PDF 批注、AI 总结、跨端同步，体验成熟。
- 没有：实验流程语义、分支决策、结构化数据表、LaTeX 报告流水线。
- 差异：通用笔记，不解决"实验数据要能算"的问题。

### 另外还有两类"部分替代"

- **通用大模型 App**（豆包 / Kimi / 通义 / ChatGPT）：拍照问"这表格是什么"能答，但不能稳定产出同一 schema 的 JSON，不积累、不可导出、不生成报告。它替代的是"这一次问答"，不是"这门课的数据资产"。
- **教学管理平台/小程序**（实验预约、报告提交）：管流程，不做识别，也不做分支答疑。

## 四、为什么还是值得自己做

1. **空白在"结构化 + 分支"**：把"照片 → 固定 schema → 实验数据资产"打通的产品很少；把"怎么判断/先做什么"做成可复用决策树的产品更少。教学场景里，后者恰恰是最花老师时间、最难沉淀的部分。
2. **教学场景对"轻"极度敏感**：学生手机型号杂、内存小、网络差。150 KB、无账号、无网也能记，是真实需求。
3. **数据资产会复利**：一学期几十张表，结构化后才能算平均值、做标准曲线、做误差分析、生成报告；OCR 出的 Excel 做不到这些闭环。
4. **可私有化**：接学校本地模型/Ollama 即可，不需要把学生数据传到第三方 SaaS。

## 五、可借鉴的点

- 表格 OCR 的**预处理**：自动裁边、透视校正、表格线检测，能显著提升识别率（LabMate 目前只做了压缩与提示词约束）。
- ELN 的**留痕**：谁在什么时候改了什么。LabMate 已存 `at / model / imageHash`，可继续加版本。
- 虚拟实验的**现象可视化**：未来可把"数据表 → 曲线图"做进报告。
- AI 笔记的**低摩擦**：打开即写。LabMate 的"载入示例 + 拍照即识别"是在往这个方向靠。

## 六、风险

- **通用助手的挤压**：如果用户只是"问一句"，豆包/Kimi 更快。LabMate 必须把价值放在"积累与产出"上（数据表、报告、分支树复用）。
- **识别准确率**：手写表格 + 拍照质量差时，任何模型都会错。产品上必须坚持"先预览、可修改、标 warnings"，不能直接入库。
- **模型成本**：识图按 token 计费。已在客户端压缩图片、限制返回长度；学校可换本地模型。
